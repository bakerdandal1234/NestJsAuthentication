تم التحقق بتاريخ 2026-10-10 من دخول Google وGitHub الحقيقيين. أتمّ المستخدم
تسجيل الدخول في المتصفح وأكد نجاح المزوّدين؛ طابقتُ النتيجة مع سجلات API
في نسخة محلية تستخدم قاعدة PostgreSQL مؤقتة. تعذّر التحكم الآلي بالمتصفح
بسبب خطأ تهيئة الأداة.

| المزوّد | callback | تبادل رمز OAuth | الطلب المحمي `/users/me` |
|---|---|---|---|
| Google، عند إعادة المحاولة | 302 | 200 | 200، أو 304 بعد تحقق الجلسة واستعمال نسخة مخبأة |
| GitHub | 302 | 200 | 200، ثم 304 عند تكرار الطلب |

في محاولة Google الأولى أعاد التبادل 401 مرتين. انتهت صلاحية رمز التبادل
عند 14:03:06.134، وكانت آخر استعادة للجلسة عند 14:03:24.907 بتوقيت
Asia/Beirut. الواجهة تنتظر استعادة الجلسة قبل التبادل، وقد تعيد الاستعادة
والطلب بعد 401. هذه التوقيتات تتوافق مع انتهاء الرمز أثناء المحاولة،
لكن السجل لا يحفظ وقت كل طلب أو سبب كل 401، لذلك لا يمكن الجزم بسبب
الاستجابة الأولى وحدها. نجحت محاولة Google التالية. لم يُحدَّد سبب
التأخير الطويل؛ لا تكفي السجلات لنسبه إلى المزوّد أو تحميل الواجهة وحده.

نجحت الاختبارات الآلية عبر `npm test`: **33/33**، منها 25 لاختبارات OAuth
و8 لإعادة كلمة المرور. تستخدم اختبارات OAuth كود Nest وPassport وقاعدة
PostgreSQL الفعلية، مع محاكاة نقاط HTTP الخاصة بالمزوّدين. تشمل state
وربط المتصفح والمزوّد، الصلاحية، إعادة الاستخدام، الطلبات المتزامنة،
ربط الحساب بالبريد الموثّق، 2FA، تجديد الجلسة، الخروج والطلبات المحمية.

هذه النتيجة تثبت المسارات والحالات المذكورة، ولا تمثل تدقيقاً شاملاً
لكل جوانب OAuth. لم يُعدَّل كود التطبيق أو تُنشأ ملفات ترحيل أثناء هذه
الخطوة؛ التغييرات تخص الاختبارات وأدوات تشغيلها والتوثيق.
